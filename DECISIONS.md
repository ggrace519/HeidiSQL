# Architecture decisions — HeidiSQL AI Edition

Decisions of the AI Edition fork. Newest last.

## ADR-001: Fork, not an upstream contribution
**Date:** 2026-10-05 · **Status:** accepted

The AI assistant is built in a fork of the upstream `lazarus` branch and is not proposed upstream.
Upstream changes are merged into the fork from time to time.

**Consequences:** fork changes should be easy to merge with upstream. New logic goes into new
units, and edits to existing upstream files are kept to small, clearly marked hooks
("AI Edition: ..." comments). Upstream `.lfm` form files are not edited; new UI is created at
runtime. Fork documentation lives in separate files (`AI-EDITION.md`, `CHANGELOG-AI.md`, this
file) instead of upstream's `README.md` and `CHANGELOG.md`, which is generated by git-cliff.

## ADR-002: Branch model `develop` → `lazarus`
**Date:** 2026-10-05 · **Status:** accepted

`lazarus` plays the role of `main` (released, and where upstream is merged in). `develop` is
the integration branch and the target of every feature PR. Promotion from `develop` to
`lazarus` is a PR merged with a merge commit, never a squash. CI runs on both branches.

## ADR-003: Separate settings folder and display name
**Date:** 2026-10-05 · **Status:** accepted

A stock HeidiSQL and the fork on the same machine would otherwise share
`~/.config/heidisql/settings.json`, `tabs.ini` and tab backups, so each would overwrite the
other's state.

**Decision:** the fork uses the sibling folder `heidisql-ai` (`APPCONFIGDIRNAME`), and shows
"HeidiSQL AI Edition" (`APPDISPLAYNAME`) in captions. `APPNAME` and `GetApplicationName` are
kept, because they also select the translation files and the client name reported to database
servers. On first start the fork offers a one-time copy of the stock settings.

## ADR-004: Own release channel, no upstream statistics
**Date:** 2026-10-05 · **Status:** accepted

The upstream update check would offer stock HeidiSQL releases to fork users, and the upstream
statistics service would count fork installations as stock ones.

**Decision:** the update check reads this fork's GitHub releases and only considers tags
starting with `ai-v`, compared against `AIEDITIONVERSION`. The fork never calls the statistics
service. `ai-v` tags keep fork releases apart from upstream `v12.x` tags mirrored in the fork.

## ADR-005: AI assistant scope and data sharing (v1)
**Date:** 2026-10-05 · **Status:** accepted

- **Providers:** the OpenAI-compatible chat completions API comes first. It covers Ollama,
  LM Studio, vLLM, OpenRouter and OpenAI, so a local model works without data leaving the
  machine. Anthropic comes later.
- **Keys:** API keys are never stored in HeidiSQL settings. They come from an environment
  variable or the OS keychain, because HeidiSQL's password storage is a reversible obfuscation
  and session exports are plain text.
- **Opt-in:** AI is enabled per session and is off by default. Provider profiles are defined
  once in Preferences, and sessions refer to a profile.
- **Shared data:** only schema information (names, types, keys, comments, approximate row
  counts) and the user's own context notes are sent. Sample rows are not sent: they are not
  needed to write SQL, and v2's read-only query tool can fetch real data on demand, with
  approval.
- **No execution:** generated SQL is never executed automatically. It is inserted into the
  editor only on request, and data-changing statements are flagged.
